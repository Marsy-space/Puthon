4. Ход выполнения работы

Шаг 1. Модель данных (`models.py`)

Создан класс `Student` (`@dataclass`) с полями `id`, `name`, `grades` и свойством `average`. Отсутствующая оценка (пустая ячейка CSV) хранится как `None`, поэтому структура «оценка за конкретный предмет» не теряется. Средний балл считается только по имеющимся оценкам; если оценок нет, он равен `0.0`.

Функции `validate_id`, `validate_name`, `validate_grade` приводят значения к нужному типу и проверяют их: `id` — целое неотрицательное число, ФИО — непустая строка, оценка — целое число от 0 до 100 (пустое значение означает отсутствие оценки). При нарушении выбрасывается `ValidationError`.

Шаг 2. Собственные исключения (`errors.py`)

text
LabError (базовое)
├── ValidationError        — некорректные данные
├── CsvFormatError         — ошибка формата CSV
├── FileAccessError        — файл не найден, нет прав
├── StudentNotFoundError   — студента с таким id нет
└── DuplicateStudentError  — студент с таким id уже есть


Шаг 3. Функции обработки (`processing.py`)

- `add_student`, `remove_student`, `update_grades`, `find_student`.
- `sort_students(students, key)`: `avg` — по убыванию среднего, затем по имени; `name` — по имени; `id` — по возрастанию. Возвращает новый список, исходный не меняется.
- `filter_by_min_average`, `filter_by_name_substring`.
- `group_stats`: количество студентов, общий средний балл по всем оценкам, лучший и худший студент. Пустой список обрабатывается без деления на ноль.
- `top_n`: первые N студентов по среднему баллу.

Шаг 4. Ввод-вывод CSV (`io_utils.py`)

- `read_students_csv`: определяет наличие заголовка (если первая ячейка первой строки не число, это заголовок), пропускает пустые строки, валидирует каждую строку. Любая ошибка оборачивается в `CsvFormatError` с номером строки. Файл читается в UTF-8 (`utf-8-sig`, чтобы без проблем читать файлы, сохранённые из Excel с BOM).
- `write_students_csv`: выравнивает число колонок `grade1..gradeN` по студенту с максимальным числом оценок, недостающие ячейки остаются пустыми. Запись идёт через временный файл с последующей заменой, поэтому файл никогда не остаётся записанным наполовину.
- `export_top_n_csv`: колонки `id, name, average, grades` (оценки в одной ячейке через пробел).
- Везде явно указаны кодировка UTF-8 и `newline=""`, пути не зашиты в код.

Шаг 5. Консольное меню (`main.py`)

Меню работает в цикле `while True` и содержит пункты: 1 — загрузка из CSV, 2 — сохранение в CSV, 3 — показ студентов, 4 — добавление, 5 — удаление по id, 6 — обновление оценок по id, 7 — статистика по группе, 8 — экспорт ТОП-N, 9 — сортировка и показ, 0 — выход.

Каждая итерация обёрнута в `try/except`: ожидаемые ошибки (`LabError`) выводятся понятным сообщением, неожиданные тоже перехватываются, программа не падает.

Запуск: `python -m lab.main`. Дополнительные аргументы командной строки:

 `--load PATH` | загрузить CSV при старте 
 `--save PATH` | сохранить CSV при выходе 
 `--top N`     | вывести ТОП-N и выйти 
 `--autosave`  | сохранять в файл из `--load` после каждого изменения

5. Дополнительно: сайт для просмотра данных со слушателем изменений

Сайт только отображает данные и не может их менять. Изменения вносятся в консольном приложении (cmd), а сайт обновляется сам.

mermaid
flowchart LR
    A[Консоль: python -m lab.main --autosave] -->|сохраняет| B[(data/students.csv)]
    B -->|слушатель замечает изменение| C[lab/serve.py]
    C -->|пересобирает| D[site/data.json]
    C -->|сигнал /events| E[Браузер: site/index.html]
    D -->|читает| E


- `publish.py` собирает из CSV файл `site/data.json` (студенты, статистика, `version` — хэш содержимого). Файл перезаписывается только при реальном изменении данных.
- `serve.py` раздаёт папку `site/` и запускает в фоне слушатель, который раз в секунду проверяет CSV. При изменении он вызывает `publish`, а открытым страницам отправляет сигнал через поток событий (`/events`). Если CSV временно нечитаем, сохраняются прежние данные.
- Страница сама перерисовывается, если изменилась версия данных. Запасной вариант — проверка раз в 30 секунд.
- Запросы на запись (POST, PUT, DELETE) сервер отклоняет с кодом 405.

Запуск (два окна cmd в корне проекта):

bash
python -m lab.serve
python -m lab.main --load data/students.csv --autosave

9. Ответы на вопросы для защиты

1. Разница между модулем и пакетом, как Python находит модули (PYTHONPATH, `__init__.py`)

Модуль — это один файл `.py` (например, `models.py`). Пакет — это каталог с модулями, обычно содержащий файл `__init__.py` (у нас пакет `lab/`). Файл `__init__.py` помечает каталог как пакет и может содержать код инициализации.

При `import` Python ищет модуль в списке `sys.path` по порядку: каталог запускаемого скрипта (при запуске через `-m` — текущий каталог), пути из переменной окружения `PYTHONPATH`, стандартная библиотека, установленные пакеты (`site-packages`).

Практический пример из работы: при запуске `python lab/main.py` в `sys.path` попадает каталог `lab/`, а не корень проекта, и `from lab.errors import ...` падает с `ModuleNotFoundError`. Поэтому приложение запускается как модуль из корня (`python -m lab.main`), а в `main.py` дополнительно добавлен корень проекта в `sys.path`.

2. Отличия списков, кортежей и словарей; когда использовать каждый

- Список (`list`) — упорядоченная изменяемая последовательность. Используется, когда набор меняется: список студентов, список оценок.
- Кортеж (`tuple`) — упорядоченная неизменяемая последовательность. Подходит для фиксированных наборов: допустимые ключи сортировки `("avg", "name", "id")`.
- Словарь (`dict`) — набор пар «ключ → значение» с быстрым доступом по ключу. Используется для именованных данных: результат статистики (`count`, `overall_avg`, `best`, `worst`).

3. Как организована сортировка в Python, ключ сортировки и стабильность

Функция `sorted(iterable, key=...)` возвращает новый отсортированный список, а `list.sort()` сортирует на месте. Параметр `key` — функция, которая для каждого элемента возвращает значение для сравнения. Сортировка в Python стабильна: элементы с равными ключами сохраняют исходный порядок.

В проекте для сортировки по среднему используется составной ключ `(-s.average, s.name.lower())`: знак минус даёт убывание по среднему, а второй элемент кортежа упорядочивает студентов с одинаковым средним по имени. Это делает результат предсказуемым (требование задания про «стабильность»). Исходный список при этом не изменяется.

4. Особенности работы с CSV (`csv.reader`/`csv.writer`, `newline`, кодировка)

Модули `csv.reader` и `csv.writer` сами обрабатывают разделители, кавычки и переносы строк внутри ячеек. Файл нужно открывать с `newline=""`, иначе на Windows появляются лишние пустые строки, а переносы внутри кавычек обрабатываются неверно. Кодировку необходимо указывать явно (`encoding="utf-8"`), чтобы кириллица читалась одинаково на любой системе.

Из практики: Excel на русской Windows открывает CSV в Windows-1251 и ждёт разделитель `;`, поэтому кириллица превращается в «РРІР°…». Решение — импорт через «Данные → Из текста/CSV» с кодировкой UTF-8. Файл «CSV UTF-8» из Excel содержит BOM, поэтому при чтении используется `utf-8-sig`.

5. Иерархия и назначение собственных исключений; когда вводить специализированный тип

В проекте базовое исключение `LabError` и наследники: `ValidationError`, `CsvFormatError`, `FileAccessError`, `StudentNotFoundError`, `DuplicateStudentError`. Базовый класс позволяет перехватить все ошибки приложения одним `except LabError` (так делает меню), а специализированные типы — реагировать на конкретную ситуацию (например, в тестах `pytest.raises(DuplicateStudentError)`).

Специализированный тип стоит вводить, когда вызывающему коду нужно отличать ошибки по смыслу и по-разному на них реагировать, а также когда нужно отделить ошибки приложения от системных (`ValueError`, `OSError`). Исходная причина сохраняется через `raise ... from exc`.

6. Алгоритм расчёта общего среднего по группе; обработка пустых наборов

Берутся все оценки всех студентов в один список (пустые `None` отбрасываются), затем считается `сумма / количество`. Это среднее по всем оценкам, а не среднее от средних баллов студентов: студент с большим числом оценок влияет сильнее.

Пустые наборы обрабатываются проверкой перед делением: если оценок нет, возвращается `0.0`. Для пустой группы количество студентов равно 0, а лучший и худший студент равны `None`. Для студента без оценок средний балл тоже `0.0`.

7. Подходы к валидации пользовательского ввода и данных из файлов

- Каждое поле проверяется отдельной функцией (`validate_id`, `validate_name`, `validate_grade`): приведение типа, диапазон, непустота.
- Одни и те же функции используются и для ввода с клавиатуры, и для строк CSV, поэтому правила едины.
- Ошибки превращаются в собственные исключения. Для CSV сообщение дополняется номером строки, для файла — причиной (не найден, нет прав, не UTF-8).
- В консольном меню ошибки перехватываются, пользователь видит сообщение и может повторить действие.
- Логические проверки (дубликат `id`, отсутствие студента) выполняются в слое обработки.
- Валидация проверяется тестами на допустимых и недопустимых значениях.

8. Что и зачем тестировать в CLI, как использовать `monkeypatch`/`capsys` в pytest

В CLI тестируют сценарии работы, а не только функции: корректный вход и выход из меню, реакцию на неверный пункт, сообщения об ошибках, что программа не падает на плохих данных, код возврата и результат работы с файлами (например, сохранение при `--autosave`).

- `monkeypatch` подменяет `input()` заранее заданной последовательностью ответов (`monkeypatch.setattr("builtins.input", lambda _="": next(inputs))`), поэтому диалог проходит без участия человека.
- `capsys` перехватывает то, что программа вывела в консоль, и позволяет проверять сообщения (`captured.out`).
- `tmp_path` даёт временную папку для файлов, чтобы тесты не трогали реальные данные.
